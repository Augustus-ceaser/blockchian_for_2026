# Phase 5.13 平台战略重定位

## 冻结结论

MedTrust Space 的正式定位为：

> **医疗 AI 可信验证与证据生产平台：医院控制的数据与模型协作基础设施，以及面向科研、监管、准入和支付等场景的可信证据生产平台。**

该定位是工程和产品方向，不是法律意见、监管认可或合规认证。公众号政策与案例材料只用于发现问题和案例线索；正式落地前必须回查适用的法律、政策、标准、地方规则及医院制度，并由法律、伦理、信息安全和研究方法专业人员独立审查。

## 核心原则

1. 数据控制权留在医院，中央平台默认不能访问原始数据。
2. 研究目的、主体、范围、期限、次数和输出在执行前版本化冻结。
3. Hospital Connector 独立验证中央指令，并拥有拒绝权。
4. 固定任务在医院控制环境执行，结果先进入医院本地隔离区。
5. 运行成功不等于允许出域；医院完成独立输出审核后才生成 EvidenceBundle。
6. 中央仅接收获批安全包、证据和必要状态，不接收本地路径、密钥或未审核患者级结果。
7. 中央与医院分别保留审计，通过摘要、签名和证据包交叉验证。

## 能力优先级

| 层级 | 能力 | 决策 |
|---|---|---|
| 核心 | 医院节点、策略核验、本地执行、隔离、出域审核、证据生产 | 下一阶段主线 |
| 核心 | 治理依据、数据质量、研究方案、适用性和持续证据 | Phase 5.14-5.15 |
| 支撑 | 目录、产品版本、申请、合约、Readiness、审计 | 保留并重新解释 |
| 外围 | 登记、上架、定价、收益分配、自动撮合 | 后移至适配层 |

不删除已实现的目录和生命周期能力，也不为术语调整立即重命名数据库表。优先以新领域对象、服务边界和页面术语叠加，避免无必要迁移。

## 已证明与未证明

当前已证明的是公开数据、固定模型、固定 20 样本、真实 CPU 执行的非临床工程闭环，以及 Artifact 隔离、多方审核、安全包、一次性下载和审计证据。

当前未证明真实医院 Connector、医院侧存储与 Executor、跨主机生产边界、生产 IAM/MFA/密钥体系、真实患者数据合法基础与伦理审批、临床有效性、国家可信数据空间认证或交易结算。
