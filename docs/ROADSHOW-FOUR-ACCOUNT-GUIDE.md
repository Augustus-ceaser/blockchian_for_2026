# 四账号路演指南

## 账号与窗口

| 窗口 | 用户名 | 默认职责页面 |
|---|---|---|
| 医院端 | `hospital.demo` | `/data-products` |
| 模型端 | `model.demo` | `/model-products` |
| 需求端 | `requester.demo` | `/applications` |
| 运营端 | `operator.demo` | `/lifecycle` |

四个窗口均从 `http://127.0.0.1:5173/demo-login` 登录。密码由本地忽略配置统一设置，文档和投屏中不得出现。

## 门户职责

- 医院端：数据产品创建/上架、数据使用审批、数据 ready、结果出域审核、产品下架/重新上架/归档申请。
- 模型端：固定模型产品创建/上架、模型许可、模型 ready、结果技术确认、产品治理申请。
- 需求端：published-only 产品选择、计算需求、合同确认、Job 创建和一次性结果下载。
- 运营端：产品上架审核、生命周期影响分析与决定、Application 预审、合同编排、资格检查、派发和平台合规审核。

## 切换规则

- 不在普通标签页中同时维持四个账号。
- 不使用前端角色切换完成正式业务。
- `/roadshow` 的“下一责任方”只提示应切换到哪个窗口，不自动替换账号。
- 可复制业务编号，不复制会话 Cookie、Token 或下载授权。

## 单机备用

如果只能使用一个窗口，必须先退出当前账号再登录下一账号，并明确说明这是单机备用演示。该方式不能用于证明四会话并发隔离；正式验收使用四个独立浏览器 Profile。
