# Phase 4 多主体可信协作模型

状态：已冻结并实现。详细对象与迁移决策见 `Phase4-multiparty-domain-freeze.md`。

## 业务边界

Phase 4 把固定 PathMNIST 工程任务提升为四方协作流程，但没有把平台扩展为任意数据或任意模型运行系统。

四类主体分别为：

- 空间运营方：目录准入、需求预审、合同编排、生效守卫、平台就绪和结果合规审核；
- 医院数据提供方：发布数据产品、审批数据用途、确认数据就绪、执行强制数据出域审核；
- AI 模型提供方：发布固定模型产品、审批模型用途、确认模型就绪、执行条件性技术质量确认；
- 数据需求企业：组合已发布的数据版本和固定模型版本提出计算需求、签署合同、创建受控任务、下载获批结果包。

## 权威链路

```text
数据产品发布 + 固定模型产品发布
→ 计算需求提交
→ 平台预审
→ 数据方与模型方并行审核
→ 四方数字合约签署
→ ContractRevision ACTIVE
→ 数据/模型/平台三方就绪
→ ComputeJob / ComputeRun
→ 固定白名单模型执行
→ quarantined Artifact
→ 数据出域审核 + 平台合规审核
→ 白名单结果包
→ 短期一次性下载授权
→ 审计完成
```

申请、审核、合约、执行、结果审核和下载均由后端命令及数据库守卫推进。前端不持有全局 `stage`，也没有通用状态修改接口。
## 不变量

- 目录只公开元数据；原始图像、宿主机路径和凭据不进入目录。
- 模型目录只引用代码内白名单入口、固定版本和摘要；不接受任意 Python 路径、Shell 命令或用户上传代码。
- 申请固定 `DataProductVersion` 和 `ModelVersion`，合同只能收窄申请范围。
- 合同生效后仍需数据、模型和平台三方就绪，才允许创建执行任务。
- 运行完成只产生隔离制品；强制审核通过也不等于自动公开原始制品。
- 结果包只允许 `aggregate_metrics.json`、`confusion_matrix.csv`、`execution_summary.json` 和未来获批报告 PDF。本次实例实际包含前三项。
- 下载授权绑定需求组织、短期有效、最多使用一次，并形成审计事件。
- `hard_isolation=false`：当前是单机工程原型，不宣称生产级沙箱、隐私计算、临床验证、医疗器械验证或国家可信数据空间测评通过。
