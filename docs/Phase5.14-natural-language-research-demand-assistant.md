# Phase 5.14 自然语言研究需求助手

状态：工程原型已实现（2026-08-27）。

## 1. 交付结果

需求企业可在现有“新建计算需求”页面输入自然语言研究问题，例如：

> 我想构建一个骨折患者住院风险预测模型

平台会生成：

- 结构化研究意图草稿；
- 稳定的澄清问题，包括结局定义、预测时点、预测窗口和人群范围；
- 仅来自当前空间已批准、有效发布、非外部 metadata-only 的数据和固定模型版本候选；
- 每个候选的匹配理由与限制；
- 与平台产品目录分开的概念方法族建议。

“分析需求”只返回瞬时预览，不保存原始输入，不创建申请。用户必须再次点击“应用需求草稿”，才会把研究描述和真正匹配的固定版本填入现有五步申请表；该动作仍不保存、不提交、不审批、不签约、不执行。

## 2. 接口

`POST /api/v1/application-assistant/recommend`

请求体：

```json
{
  "demand_text": "使用入院时可获得的成人骨折结构化电子病历，预测入院后30天内再入院风险，用于科研分析"
}
```

约束：

- 仅 `data_requester`；
- 文本去除首尾空白后为 10 至 2000 字符；
- 无数据库写入、无推荐会话持久化、无外部 LLM 或网络调用；
- 候选池与 `GET /application-options` 共用同一个治理过滤和公开字段投影。

响应状态：

- `blocked`：个人诊疗、临床用途、原始病历导出或越权指令；
- `needs_clarification`：关键研究定义不完整；
- `catalog_gap`：研究定义完整，但目录缺少合适的数据或固定模型版本；
- `ready`：研究定义完整，且数据与固定模型版本均存在初步匹配。

## 3. 必须诚实显示的目录结果

当前目录如果只有 PathMNIST 数字病理数据和 ResNet-18 图像分类模型，骨折住院风险需求必须返回真实的目录缺口，不能把病理图像资产伪装成骨折住院队列或风险模型。

匹配器还会分别核验登记模态和具体预测结局：`histopathology` 不会因包含字符 `his` 而被当成医院 HIS 数据，院内死亡模型也不能替代再入院模型。

Logistic 回归、梯度提升树等仅作为方法族建议返回，并明确标记：

- `registered=false`；
- `executable=false`；
- 不代表平台已拥有、可执行或已验证该模型。

## 4. 工程与安全边界

本阶段明确保持：

- `research_only=true`；
- `recommendation_only=true`；
- `clinical_use=false`；
- `auto_approval=false`；
- `auto_training=false`；
- `creates_application=false`；
- `creates_compute_job=false`；
- `raw_data_access=false`；
- 研究草稿要求仅使用预测时点之前可获得的信息；
- `temporal_leakage_check_enforced=false`：当前版本尚未自动执行字段级时序泄漏核验，仍需后续兼容性检查与人工审核确认；
- `hard_isolation=false`。

因此，本功能不是患者自助诊疗入口，也不是自动训练平台。当前申请链仍要求选择已发布固定数据版本和已发布固定模型版本，并继续经过服务端兼容性检查、多方审核与数字合约。

## 5. 本阶段未增加

- 无 ORM 或数据库迁移；
- 无患者角色；
- 无模型训练、任意代码或任意模型执行；
- 无患者级预测输出；
- 无原始数据或模型权重下载；
- 无生产隔离、临床有效性或安全认证声明。
