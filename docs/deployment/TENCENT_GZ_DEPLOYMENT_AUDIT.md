Coordinator, callback worker, Hospital Connector, and Hospital Executor are
not required for catalog, application, contract, and governance web access.
They are intentionally absent from the default 2-core/4GB central deployment.

## Actual Build and Routing

- `gateway/Dockerfile` builds the React application with pnpm, then serves it
  from Caddy 2.10.2 on port 8080 as fixed UID/GID `10000:10000`.
- `/api/*` is proxied by the internal Gateway to `backend:8000`.
- `/docs` and `/openapi.json` are disabled in deployed modes.
- No WebSocket, SSE, or application streaming route was found.
- The public Caddy edge proxies only to `gateway:8080`; it does not proxy to a
  host-published Backend.

## Backend Configuration and Security

Actual application variables use the `MEDTRUST_` prefix. The deployment uses:

- `MEDTRUST_APP_ENV=production`
- `MEDTRUST_DEPLOYMENT_MODE=pre-icp|public-alpha`
- `MEDTRUST_PUBLIC_ORIGIN`, `MEDTRUST_TRUSTED_ORIGINS`,
  `MEDTRUST_CORS_ORIGINS`, and `MEDTRUST_ALLOWED_HOSTS`
- `MEDTRUST_TRUSTED_PROXY_IPS`
- file-backed database, MinIO, and five invitation-account credentials
- configurable session lifetime, password minimum, and login rate limit
- `MEDTRUST_DEMO_API_ENABLED=false`
- `MEDTRUST_ENABLE_DEMO_ROLE_SWITCH=false`

Sessions are random bearer values stored only as SHA-256 digests in the
database. There is no JWT, application Session Secret, or separate CSRF Secret.
CSRF protection uses trusted Origin/Referer enforcement for cookie-authenticated
write requests. Cookies are HttpOnly and SameSite=Lax; Secure is enabled only
in Public mode because Pre-ICP access is loopback HTTP through SSH.

Self-registration does not exist. The real current administrator mechanism is
the seeded `operator.demo` role. `bootstrap_public_alpha.py` initializes the
Synthetic Phase 4 graph and invitation credentials from root-only secret
files, then reports only the operator username and object ID.

## Migration

- Alembic command: `alembic upgrade head`
- Current single head: `20260730_0058`
- `migrate.sh` waits for PostgreSQL, asserts one head, upgrades, prints current
  version, and checks critical tables.
- Public deployment starts with a new named PostgreSQL volume. No local
  database, SQLite file, or volume snapshot is copied.

## Storage and Keys

- PostgreSQL, MinIO, backend storage, policy signing, and Caddy data use named
  volumes.
- Policy signing keys are generated by existing application logic under
  `/var/lib/medtrust/policy-signing` and remain in the dedicated named volume.
- Hospital Evidence signing keys belong to Hospital Connector deployments;
  the central Public Alpha receives only certificates and verified receipts.
- No Phase 5.13 test key is packaged.

## Resource Budget

| Service | Memory | CPU |
|---|---:|---:|
| PostgreSQL | 768MB | 0.50 |
| MinIO | 512MB | 0.40 |
| Backend | 768MB | 0.65 |
| Dispatcher | 256MB | 0.25 |
| Gateway | 128MB | 0.15 |
| Public Caddy | 128MB | 0.15 |

Default Pre-ICP total is 2.375GB; Public total is 2.5GB. Remaining RAM is
reserved for Ubuntu, Docker, page cache, and transient operations. Build
parallelism is one. A 4GB swap file is recommended only as OOM buffering.

Backend and Gateway run as fixed non-root users. The Public-mode edge Caddy is
the documented compatibility exception: it needs to bind 80/443 and write its
certificate volumes. It has only `NET_BIND_SERVICE`, drops all other
capabilities, uses `no-new-privileges`, and has no Docker socket or host
network.

## Disk Risk

- Warn below 15GB free.
- Block builds/upgrades below 8GB free.
- Docker JSON logs rotate at 10MB × 5 per service.
- Backup retention defaults to seven daily backups.
- `docker builder prune --filter until=168h` is the safe cache-only cleanup;
  never prune volumes or all images blindly.

## Build Options

- Server build is supported and sequentially builds Backend then Gateway.
- Local source packaging is supported through `git archive`.
- Local OCI image export/import is not implemented in this package. The
  server therefore needs access to pinned base images and package registries
  during its first build.

## Deployment Blockers and Limits

- Public mode is blocked until the real ICP number, domain, DNS, and manual
  80/443 firewall gate are complete.
- The Public edge has not been started locally or remotely and no ACME request
  has been made.
- Login rate limiting is in-process and assumes the configured single Uvicorn
  worker. A shared limiter is required before horizontal scaling.
- The current invitation accounts do not implement mandatory first-login
  password rotation.
- Backups remain on the same server until an encrypted off-host/COS copy is
  added.
- This is not production isolation, clinical validation, legal advice, or
  compliance certification.
