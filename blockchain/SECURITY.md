# 安全说明

## 当前安全状态

本目录仅用于本地工程演示。合约和脚本**尚未经过独立第三方安全审计**，不应被视为生产就绪、医疗合规、金融合规或法律合同基础设施。

- `MockSettlementToken` 没有真实价值，演示过程没有真实资金。
- 不得把当前合约部署到任何主网，也不得托管真实资产。
- 不得把患者信息、身份材料、合同正文、模型权重、任务输出或可反推这些内容的低熵值直接写入链上。

## 本地原型试图保持的安全不变量

1. 每个参与方在确认合同时必须持有对应且未过期、未撤销的角色凭证。
2. 资格、合同登记与托管三个合约在部署时必须绑定同一个非零空间摘要；一个部署只服务一个数据空间。
3. 同一地址不能重复确认；非合同参与方不能确认；空间运营方只能在前三方全部确认后最后确认。
4. 合同有效期已开始时，4-of-4 确认在一次交易内把状态推进为 `Active`，避免登记方人为拖延激活。
5. 只有活跃合同的需求方能创建托管，创建时四方角色凭证必须全部有效。
6. 每次接收执行/交付证明前，合约都会重新核验数字合约仍生效且四方角色凭证仍有效。
7. 执行证明与交付证明由两个不同的授权地址提交；单一证明不能释放费用。
8. 结算只增加受益人的 `claimable` 余额，受益人自行提现，避免一个接收方阻塞其他接收方。
9. 已结算订单不能退款，已退款订单不能再结算；状态更新和代币转移受重入保护。
10. 对采用 Web3 托管的订单，链下结果下载授权在托管进入 `claimable` 前保持关闭；旧式演示支付流程不受此门禁影响。

这些是不变量目标，而不是审计结论。

## 已知边界与残余风险

- **集中化权限**：凭证签发/撤销、合同登记/结束、暂停和两类证明仍依赖指定管理地址或证明方。测试账户不是安全治理方案。
- **不是完整 DID/KYC**：当前 SBT 风格凭证由发行方背书，没有实现去中心化标识解析、可验证凭证展示、选择性披露或零知识资格证明。
- **不是通用多签钱包**：4-of-4 是业务状态机。参与方密钥遗失、更换、机构合并、紧急替换和多签内部治理尚无处理流程。
- **当前只支持 EOA**：SIWE 只验证 EOA `personal_sign`，回执同步要求交易直接调用目标合约；Safe/DAO 的 EIP-1271 签名及内部调用尚未实现。
- **链上广播与数据库提交不是原子事务**：本地流程会在广播后立即保存交易哈希，并在重试时优先恢复同一回执，避免正常中断后重复发送；但广播成功而数据库提交尚未完成之间仍存在极小故障窗口。生产环境必须使用持久 outbox、事件索引、业务键查链和可重试状态机彻底闭合该窗口。
- **演示收款地址复用角色钱包**：本地托管把医院、模型方和运营方的角色钱包同时用作收款地址；生产合同必须单独冻结机构金库地址并完成财务授权。
- **撤销会影响结算可用性**：托管后若合约暂停/终止或任一方凭证失效，证明提交会失败，需求方只能等待超时退款；尚未实现争议期内的管理员仲裁。
- **证明方仍是信任根**：链只能证明哪个授权地址提交了哪个摘要，不能独立证明计算真实运行、数据合规或交付内容正确。
- **没有争议仲裁**：当前只有双证明结算与超时退款，没有部分退款、拒付、申诉、仲裁或人工冻结订单的状态。
- **时间与排序风险**：到期附近的证明和退款由区块时间及交易排序决定；尚未定义业务上的宽限期和链拥堵策略。
- **隐私与关联性**：公开地址、金额、时间和摘要仍可能形成行为关联；低熵原文的裸摘要可能被字典攻击。生产摘要必须使用规范化、域分离和随机盐策略。
- **域分离仍需生产复核**：受控任务和两类证明摘要已包含链 ID、托管合约地址、订单键和版本，SIWE 包含 domain、URI、chain ID 与 nonce；上线前仍须对所有新摘要和链下签名协议逐一审计域分离与重放边界。
- **最终性同步仍是本地级别**：后端会通过固定可信 RPC 核验链 ID、合约地址、事件参数、规范区块和最低确认数，并用交易哈希与日志序号幂等入库；但尚无生产级持续索引器、链重组回滚、RPC 冗余、断点追赶、告警与人工对账。
- **部署预检尚未达到生产级**：本地一键脚本部署并传递同一份清单，后端会校验地址、链 ID 和空间摘要；通用部署启动时尚未用 `eth_getCode` 与只读合约调用逐一验证实际字节码、依赖地址、角色授权和代币精度。
- **凭证发行仍是受控信任根**：签发/撤销事件已明确携带 indexed issuer，后端会把它与配置的发行钱包、直接交易发送方、目标合约及事件字段逐项核验；但生产环境仍需要持续索引合约角色变更，并用多签/HSM 管理发行权限。
- **Mock 代币不代表真实支付**：未评估真实代币的冻结、黑名单、手续费、升级、精度、许可和监管行为。
- **不可升级**：合约没有升级机制；错误修复需要迁移、新地址和业务状态迁移方案。

## 上主网或接入真实业务前的最低门槛

- 冻结需求和威胁模型，补齐角色更换、争议、紧急暂停、迁移及恢复流程。
- 使用成熟多签与时间锁管理管理员权限，分离发行、登记、暂停、执行证明和交付证明的组织控制。
- 为证明引入可验证签名、硬件密钥、明确的证明格式、域分离和吊销机制；评估是否需要去中心化预言机。
- 增加单元测试、属性测试、状态机模糊测试、静态分析和形式化不变量验证，覆盖恶意/异常 ERC-20 与所有边界时间。
- 至少完成一次独立智能合约安全审计，修复发现并对最终部署字节码复审；高风险变更后重新审计。
- 设计链上事件到 PostgreSQL 的幂等同步、确认数、重组回滚、告警和人工对账，不把“已广播”误认为“已最终确认”。
- 完成钱包签名登录的 nonce、防重放、来源域、chain ID、合约地址、会话过期和账户切换处理。
- 完成隐私影响、数据保护、医疗合规、支付/资金托管、税务和数字合同法律效力审查。
- 在隔离测试网进行容量、故障恢复、密钥轮换和事件响应演练后，再由审计方及治理方共同批准部署。

## 漏洞报告

如果发现潜在漏洞，请避免公开利用细节或在任何真实网络复现。优先通过仓库启用后的 GitHub Private Vulnerability Reporting / Security Advisory 私下提交；若该渠道尚未配置，请先联系仓库维护者建立私密通道。当前仓库不承诺生产级漏洞赏金或响应时限。
